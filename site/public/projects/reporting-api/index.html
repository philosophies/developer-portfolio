Enterprise Reporting API

A small reporting service with inspectable database rules and tested HTTP behavior. This is a runnable local backend, using synthetic data; the page you are reading is a static case study.

Source & setup ↗Integration tests ↗

THE PROBLEM

Summarize records without hiding exceptions.

Operations and Finance need totals for an explicit date range, with exception counts alongside the money. Three synthetic records make the result independently checkable.

Request → validation → SQL → report

Data boundaries

PostgreSQL enforces unique external IDs, non-negative amounts and known statuses. Reapplying the seed does not duplicate records. A date index supports range filtering.

API boundaries

The endpoint uses bound parameters and cancellation. It validates date order and limits results to at most 100 departments. Invalid dates, ranges and limits return HTTP 400.

Evidence

Six HTTP integration tests passed against PostgreSQL 17: four invalid-query cases, exact seeded aggregation and a date range that excludes all records. The implementation uses ASP.NET Core’s test host rather than replacing database behavior with a mock.

Run locally

Follow the source README to start the isolated Docker database, set the connection string, run the API and execute the tests. The included password belongs only to the synthetic local demo.
