Enterprise Reporting API

An authenticated record-review service with tenant boundaries, independent approval, corrections and transactional audit history. This is a runnable local backend using synthetic data; the linked workbench is an interactive browser simulation.

THE PROBLEM

Review changes before they reach the report.

Operators create and submit records. A different reviewer approves or rejects them. Corrections return records to draft, and only approved records enter report totals. Every change is tied to an actor, version and reason where required.

Draft → submitted → approved or rejected

Correction → draft → resubmission. An owner cannot approve their own submission. Pending submissions cannot be edited.

Data boundaries

PostgreSQL enforces tenant-scoped external IDs, non-negative amounts, known states and version numbers. Checksummed migrations are explicit and repeatable. Record and audit writes share one transaction.

API boundaries

Signed bearer tokens supply identity and tenant claims. Owners see their own records; reviewers remain within their tenant. Cursor pagination, request-size bounds, rate limits and expected-version checks keep behavior explicit.

Evidence

28 HTTP/database integration cases passed against PostgreSQL 17, including expired or incorrectly signed tokens, tenant and owner boundaries, self-review prevention, concurrent edits, audit-write rollback, append-only history, pagination and migration checksum protection. The actual JWT middleware and database are exercised.

Run locally

Follow the source README to start the isolated Docker database, set the connection string, run the API and execute the tests. The included password belongs only to the synthetic local demo.

Measured SQL behavior

A reproducible study on 100,000 temporary synthetic rows changed the selective aggregation plan from a sequential scan to a bitmap index scan. One local execution measured 6.647 ms before the partial index and 0.311 ms after. These are observations from one local run, not production promises.

Deployment package and remaining work

A non-root .NET container image is provided. The service includes database readiness checks, structured transition logs and explicit migration commands. Production startup requires a trusted HTTPS identity provider and audience. A typed React interface now supports the workflow, with a real HTTP adapter for local API use and a clearly labeled sample mode on this site. Managed PostgreSQL hosting, production provider sign-in and backup/restore verification remain next steps. The API is not currently exposed publicly.
