Correct the record. Keep the history.

A small SQL Server exercise that makes rollback, stale edits and query plans inspectable.

The stored procedure corrects an owned record using a tenant, owner and expected version, then records the old and new amounts in the same transaction. A correction returns the record to draft so it leaves approved totals. This is a standalone synthetic-data exercise, not a second deployed backend.

When the second write fails

A test trigger deliberately rejects an audit insert. The procedure rolls back; both the record amount and its version stay unchanged. Other checks cover stale or missing versions, scoped lookups, invalid amounts, blank reasons and append-only history. All 13 checks passed on SQL Server 2022 Developer Edition.

A plan you can inspect

A separate 100,000-row fixture runs the same aggregation before and after a covering index. Both return 122216.00. The local actual plan changes from a clustered index scan to an index seek; reported logical reads change from 1860 to 4. These are observations from one fixture and run, not a production speedup promise.

Scope and identity

The runner starts a disposable non-production container without published ports and cleans it up afterward. Credentials are generated for that run. Procedure parameters do not authenticate a caller; a real application must supply scope from trusted identity. There is no SQL Server HTTP deployment, provider sign-in or concurrent-session test here.
