Reporting Workbench & API

An ASP.NET Core record-review workflow with signed bearer authentication, tenant boundaries, independent approval, corrections and transactional audit history.

The hosted workbench uses synthetic records. The local API has 28 integration cases covering permissions, concurrency and audit rollback.

Explore the design

GET /api/reports accepts a date range and a bounded result limit. SQL groups amounts and exceptions by department. Invalid ranges return 400. The API requires validated bearer tokens and enforces tenant/owner boundaries. Only approved records enter totals; corrections require another review.

02 / HOW I APPROACH THE WORK

Make the behavior
easy to explain.

Keep the data honest.

Constrained schemas, parameterized queries, and fixtures that let someone else check the result.

Plan for the awkward cases.

Stale edits, missing permissions, failed writes. Those paths deserve just as much attention as the happy one.

Leave a trail.

Small pull requests, useful tests, and an audit history that explains what changed and why.
